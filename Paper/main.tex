%  ABSTRACT
% ============================================================
\begin{abstract}
Scheduling computational workflows represented as Directed Acyclic
Graphs (DAGs) onto heterogeneous Virtual Machines (VMs) is a
fundamental NP-hard problem in cloud computing. This paper presents
and compares the schedulers implemented in the C++17 framework: (1)
\emph{HEFT} as the classical baseline, (2) \emph{DP-HEFT} with
bilateral-rank and 2-task look-ahead (reported by the program as
\texttt{"HEFT + DP"}), (3) \emph{Enhanced DP (EDP-HEFT)} with a
full global DP assignment, (4) \emph{Divide-and-Conquer} (D\&C) with
level decomposition, (5) the greedy \emph{Min-Min} level heuristic
(implemented as \texttt{scheduleLevel MinMin} in \texttt{merge.cpp}),
and (6) \emph{Merge}, a hybrid scheduler (reported by the program as
\texttt{"Optimization Algorithm (OP)"}) that adaptively selects per-
level strategies and applies refinement. All methods share a unified
communication-cost model and a reproducible DAG generator. Comparative
analysis highlights the complexity–quality trade-off between fast
greedy heuristics and more expensive global/refined optimisation.
\end{abstract}

DAG scheduling, cloud computing, HEFT, dynamic programming,

\section{Introduction}
\label{sec:intro}

Cloud computing platforms increasingly execute scientific and
enterprise workflows as Directed Acyclic Graphs (DAGs), where each
node is a computational task and each directed edge encodes a data
dependency~\cite{deelman2009workflows,buyya2009cloud}. The
scheduling problem — assigning tasks to heterogeneous Virtual
Machines (VMs) while minimising total completion time (makespan) —
is NP-hard in the
general case~\cite{ullman1975np,garey1979computers}, motivating
a rich body of heuristic research.

The seminal Heterogeneous Earliest Finish Time (HEFT)
algorithm~\cite{topcuoglu2002heft} achieves near-optimal makespan
through upward-rank prioritisation combined with an Earliest Finish
Time (EFT) insertion policy. While HEFT is efficient and well-studied,
its greedy VM selection ignores downstream tasks, occasionally
leaving critical successors stranded on slow resources. Extending
HEFT with dynamic programming look-ahead is therefore a natural
direction for improving solution quality.

This paper makes the following contributions:
\begin{enumerate}
      \item \textbf{HEFT Baseline}: A faithful greedy HEFT implementation
                        used as the classical reference for makespan and complexity
                        comparison in the same C++17 environment.
  \item \textbf{DP-HEFT}: A HEFT extension that uses bilateral rank
        (upward rank + downward rank) for task prioritisation and a
        weighted 2-task look-ahead DP for VM assignment, scoring each
        candidate as $\EFT(t_i) + 0.25 \cdot \EFT^*(t_{i+1})$.
  \item \textbf{EDP-HEFT}: An enhanced variant that constructs a full
        $n \times m$ DP table over the bilateral-rank priority order,
        propagating scheduling snapshots to achieve globally optimal
        VM assignments within that order, and backtracking to recover
        the optimal sequence.
  \item \textbf{D\&C Scheduler}: A divide-and-conquer approach that
        decomposes the DAG into independent topological levels via BFS,
        schedules each level as a sub-problem, and merges partial
        schedules with cross-level dependency and communication cost
        awareness.
  \item \textbf{Merge Scheduler}: A hybrid merge strategy that
        adaptively switches among D\&C, DP look-ahead, and EDP-style
        global assignment, followed by refinement passes to reduce
        bottlenecks and improve final makespan.
  \item A shared C++17 implementation including a probabilistic DAG
        generator with reproducible fixed seeding, an exhaustive
        8-check validator, and a unified output model enabling
        direct metric comparison.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\subsection{List Scheduling and HEFT}

Kwok and Ahmad~\cite{kwok1999static} provided a comprehensive
taxonomy of static DAG scheduling algorithms, establishing upward
rank as the dominant prioritisation criterion. Topcuoglu
\textit{et al.}~\cite{topcuoglu2002heft} introduced HEFT and CPOP,
demonstrating that upward-rank sorting with EFT insertion consistently
achieves lower makespan than random or FIFO ordering on heterogeneous
systems. Arabnejad and Barbosa~\cite{arabnejad2014cpop} extended this
work with an Optimistic Cost Table (OCT) that approximates future
communication costs, improving makespan by up to 12\% on standard
benchmarks. Hagras and Jane\v{c}ek~\cite{hagras2003static} proposed
HBMCT, which combines task duplication with heterogeneity-aware
priority.

\subsection{Look-Ahead and DP Extensions}

Bittencourt \textit{et al.}~\cite{bittencourt2018heft} introduced
HEFT-NC (No Communication), demonstrating that look-ahead awareness
of immediate successors yields measurable makespan reductions.
Sakellariou and Zhao~\cite{sakellariou2004hybrid} proposed a hybrid
scheduler combining list scheduling with task duplication, exploiting
idle processor windows. Bajaj and Agrawal~\cite{bajaj2004improving}
formalised the bilateral rank ($\ranku + \rankd$) and showed it
captures both path-criticality and positional importance, outperforming
pure upward-rank ordering.

\subsection{Divide-and-Conquer Scheduling}

Dong \textit{et al.}~\cite{dong2007divide} applied level-based
decomposition to Grid scheduling, independently optimising intra-level
task placement. Canon \textit{et al.}~\cite{canon2008comparative}
benchmarked decomposition heuristics against list schedulers on
standard DAG suites, finding that level-based methods perform
competitively on shallow graphs but degrade on deep critical paths.

\subsection{Cloud Workflow Scheduling}

Pandey \textit{et al.}~\cite{pandey2010particle} adapted Particle
Swarm Optimisation for cloud workflow scheduling, reporting cost
reductions over greedy baselines. Ma \textit{et al.}~\cite{ma2023survey}
provide a recent survey of DAG scheduling in cloud computing,
identifying bilateral-rank heuristics and DP-based methods as among
the most effective approaches for minimising makespan on heterogeneous
resources.

\subsection{Positioning}

Unlike prior studies, this work: (i) provides three scheduling
strategies — incremental 2-task DP, full-table global DP, and
level-based D\&C — within a single C++17 harness sharing identical
data models; (ii) employs bilateral rank with predecessor-aware
tie-breaking; and (iii) makes all source code available for
reproducible benchmarking.

\section{Problem Formulation}
\label{sec:problem}

\subsection{DAG Workflow Model}

A workflow application is modelled as a DAG
$G = (\mathcal{T}, \mathcal{E})$, where:
\begin{itemize}
  \item $\mathcal{T} = \{t_0, t_1, \ldots, t_{N-1}\}$ is the set of
        $N$ computational tasks.
  \item $\mathcal{E} \subseteq \mathcal{T} \times \mathcal{T}$ is the
        set of directed dependency edges. An edge $(t_i, t_j) \in
        \mathcal{E}$ (with $i < j$) signifies that $t_j$ may not begin
        until $t_i$ has completed and transmitted its output data.
\end{itemize}

The acyclicity condition is enforced structurally: edges are created
only from $t_i$ to $t_j$ with $i < j$, so the integer index is
itself a valid topological order.

\subsection{Heterogeneous Resource Model}

A cloud data centre is modelled by $M$ heterogeneous VMs
$\mathcal{V} = \{v_0, v_1, \ldots, v_{M-1}\}$. Each VM $v_k$ has a
speed factor $s_k \in [s_{\min}, s_{\max}]$ drawn uniformly at
random. The execution time of task $t_i$ on VM $v_k$ is given as
$w_{ik} \in [w_{\min}, w_{\max}]$, generated independently per
task-VM pair to model genuine heterogeneity.

\subsection{Communication Cost Model}

When task $t_i$ (assigned to VM $v_p$) produces data consumed by
task $t_j$ (assigned to VM $v_q$), the inter-VM data transfer incurs
a communication delay modelled as:
\begin{equation}
      c(t_i, v_p, t_j, v_q) =
      \begin{cases}
            0 & \text{if } p = q,\\
            \kappa \cdot \bar{w}_i & \text{otherwise,}
      \end{cases}
      \label{eq:comm}
\end{equation}
where $\bar{w}_i = \frac{1}{M}\sum_{k=0}^{M-1} w_{ik}$ is the
average execution time of task $t_i$ across all VMs. In the
implemented C++ framework the communication multiplier (here denoted
by $\kappa$) is computed dynamically by the DAG generator
(function \texttt{calculateCommCostFactor()} in \texttt{dag\_generator.cpp})
based on graph density, execution-time granularity and VM heterogeneity.
This computed \texttt{commCostFactor} is stored in \texttt{DAGData} and
used uniformly by all schedulers (see \texttt{dag\_generator.cpp}).

\subsection{Scheduling Objective}

A schedule $\sigma : \mathcal{T} \to \mathcal{V}$ assigns each task
to exactly one VM. The performance metric is the \emph{makespan}:
\begin{equation}
  C_{\max}(\sigma) = \max_{t_i \in \mathcal{T}}\; \EFT(t_i, \sigma(t_i)),
  \label{eq:makespan}
\end{equation}
where $\EFT(t_i, v_k)$ denotes the Earliest Finish Time of task
$t_i$ on VM $v_k$ under schedule $\sigma$. The scheduling problem
is:
\begin{equation}
  \sigma^* = \argmin_{\sigma}\; C_{\max}(\sigma).
  \label{eq:opt}
\end{equation}

Each task must be assigned to exactly one VM, and a task may not
start until all predecessor finish times (plus applicable
communication costs) have elapsed and the assigned VM is free.

\begin{enumerate}
  \item \textbf{Generator \& Validator Layer} (\texttt{dag\_generator.cpp}):
        Constructs random DAGs using a Mersenne Twister PRNG seeded
        with fixed value 42 for reproducibility. Enforces eight
        structural invariants.
  \item \textbf{Model Layer} (\texttt{dag\_generator.h},
        \texttt{AlgorithmResult.h}): Defines the shared data

  \item \textbf{Algorithm Layer} (\texttt{dp.cpp}, \texttt{Edp.cpp},
        \texttt{dac.cpp}, \texttt{heft.cpp}, \texttt{merge.cpp}): Each algorithm exposes a single function
        returning an \texttt{AlgorithmResult} printable by the shared
        \texttt{printAlgorithmResult()} routine.
\end{enumerate}

\subsection{Data Structures}

The core data types, defined in \texttt{dag\_generator.h} and
\texttt{AlgorithmResult.h}, are:

\begin{itemize}
  \item \texttt{Task}: holds task id, predecessor list, successor
        list, and a per-VM execution time vector
        (\texttt{std::vector<double>\ execTimes}).
  \item \texttt{VM}: holds VM id and a floating-point speed factor.
  \item \texttt{DAGData}: aggregates all tasks and VMs into a single
        container passed by constant reference throughout the pipeline.
  \item \texttt{ScheduleEntry}: records task id, assigned VM id,
        start time (\texttt{startTime}), and finish time
        (\texttt{finishTime}) for a single task.
  \item \texttt{AlgorithmResult}: wraps a vector of
        \texttt{ScheduleEntry} objects, the overall makespan, the
        wall-clock runtime in milliseconds, and a validity flag.
\end{itemize}

\subsection{Execution Flow}

\texttt{main.cpp} executes the following pipeline:
\begin{enumerate}
  \item Generate a DAG with the implementation defaults
        (\texttt{DEFAULT\_NUM\_TASKS = 40} tasks and
        \texttt{DEFAULT\_NUM\_VMS = 7} VMs as declared in
        \texttt{dag\_generator.h}).
  \item Print the full DAG structure (VM speed factors, per-task
        adjacency lists, per-VM execution times).
  \item Validate the DAG against eight structural checks.
      \item Invoke \texttt{heft\_schedule()}, print result.
      \item Invoke \texttt{dp\_heft()}, print result.
      \item Invoke \texttt{edp\_heft()}, print result.
      \item Invoke \texttt{dac\_schedule()}, print result.
      \item Invoke \texttt{merge\_schedule()}, print result.
\end{enumerate}

\subsection{DAG Generation}

The \texttt{generateDAG()} function builds the DAG in three stages:
(1) VMs are created with speed factors drawn from
$\mathcal{U}(0.5,\,2.0)$; (2) tasks are created with execution times
drawn from $\mathcal{U}(1.0,\,20.0)$ per VM; (3) for every ordered
pair $(i,j)$ with $i < j$, edge $t_i \to t_j$ is added with
probability $p_e = 0.35$. Acyclicity is guaranteed by construction
since $j > i$ always holds. The generator uses a fixed Mersenne
Twister seed (42) for reproducibility. The implementation also
computes a data-transfer multiplier (stored as \texttt{commCostFactor})
from graph and VM statistics rather than using a hard-coded constant.

\subsection{DAG Validation}

Eight structural checks are applied:
(A)~\texttt{execTimes.size()} $== M$ for every task;
(B)~no self-loops;
(C)~all predecessor/successor indices within $[0,N)$;
(D)~bidirectional consistency (if $A$ lists $B$ as successor,
$B$ must list $A$ as predecessor);
(E)~acyclic ordering ($j > i$ for every edge $t_i \to t_j$);
(F)~at least one entry node (no predecessors);
(G)~at least one exit node (no successors);
(H)~no duplicate edges in either list.

\section{Scheduling Algorithms}
\label{sec:algorithms}

This section presents the five top-level schedulers and the greedy Min-Min
level heuristic implemented in the framework.
All methods share the EFT-based feasibility model in
Section~\ref{sec:problem} and the communication model in
Eq.~\eqref{eq:comm}.

\subsection{HEFT (Baseline)}

HEFT~\cite{topcuoglu2002heft} computes upward ranks, sorts tasks in
descending $\ranku$, and greedily assigns each task to the VM yielding
the minimum EFT. In this study, HEFT serves as the classical baseline
for both makespan and computational overhead.

\begin{algorithm}[!t]
\caption{HEFT Scheduling (Greedy EFT)}
\label{alg:heft}
\begin{algorithmic}[1]
\STATE Compute $\ranku(t)$ for all tasks $t \in \mathcal{T}$
\STATE Sort tasks by descending $\ranku$
\FOR{each task $t$ in sorted order}
    \STATE For each VM $v_k$, compute $\EST(t,v_k)$ and $\EFT(t,v_k)$
    \STATE Assign $t$ to $v^* = \argmin_{v_k} \EFT(t,v_k)$
    \STATE Update VM availability and task finish time
\ENDFOR
\STATE \textbf{return} complete schedule and makespan
\end{algorithmic}
\end{algorithm}

\textbf{Overview:} HEFT is a lightweight list-scheduling heuristic
that prioritises tasks by upward rank and assigns each task to the VM
with minimum EFT. It is fast and forms the baseline for comparisons.

\textbf{Workflow:} compute $\ranku$, sort tasks, evaluate EST/EFT on
each VM for the current task, and commit the minimal-EFT assignment.

\textbf{Complexity:} $O(n\log n + m\cdot(n+e))$ time and
$O(n+m+e)$ space (matches the implementation in \texttt{heft.cpp}).

\textbf{Strengths/Limitations:} very fast and simple; may be myopic
because it ignores downstream effects beyond rank information.

\textbf{Role:} baseline fast scheduler used to quantify improvements
from DP look-ahead and global optimisation in subsequent methods.

\subsection{DP-HEFT}

\textbf{Overview:} DP-HEFT augments HEFT by using bilateral rank
($\ranku+\rankd$) for prioritisation and a lightweight 2-task dynamic
programming look-ahead to reduce myopic VM choices.

\textbf{Workflow:} compute $\ranku$ and $\rankd$, form bilateral rank
and sort; for each task evaluate each VM's EFT and the impact on the
next task by temporarily committing the assignment; score candidates
with the weighted sum and select the minimum.

\begin{algorithm}[!t]
\caption{DP-HEFT (Bilateral-Rank + 2-Task Look-Ahead)}
\begin{algorithmic}[1]
\STATE Compute $\ranku(t)$ and $\rankd(t)$ for all $t$
\STATE Compute $\mathrm{biRank}(t) \leftarrow \ranku(t)+\rankd(t)$
\STATE Sort tasks by descending $\mathrm{biRank}$ to obtain priority list
\FOR{each task $t_i$ in priority order}
      \FOR{each VM $v_k$}
            \STATE Compute $\EST(t_i,v_k)$ and $\EFT(t_i,v_k)$
            \STATE Temporarily commit $t_i\to v_k$ and compute best $\EFT^*(t_{i+1})$
            \STATE $\mathrm{score} \leftarrow \EFT(t_i,v_k) + 0.25\cdot\EFT^*(t_{i+1})$
      \ENDFOR
      \STATE Assign $t_i$ to VM with minimal score and update VM state
\ENDFOR
\STATE \textbf{return} complete schedule and makespan
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:} $O(n\log n + n m^2 + m e)$ time in the worst case,
matching the implementation in \texttt{dp.cpp}; space is $O(n+m+e)$.

\textbf{Strengths/Limitations:} reduces local greediness with a cheap
look-ahead, improving makespan at modest extra cost; still limited to
considering only the immediate successor in scoring.

\textbf{Role:} practical middle-ground between pure greedy HEFT and
full global DP; useful when modest runtime overhead is acceptable.

\subsection{EDP-HEFT}

\textbf{Overview:} EDP-HEFT builds a full dynamic programming table
across the priority-ordered tasks and possible VM assignments, thereby
finding the best sequence of VM choices under the fixed bilateral-rank
order.

\textbf{Workflow:} derive bilateral-rank priority; for each task index
and each VM maintain the best achievable makespan and a snapshot of
the scheduling state; propagate these states forward, record parent
pointers, and backtrack to recover the optimal assignment for the
priority order.

\begin{algorithm}[!t]
\caption{EDP-HEFT (Full Global DP over Priority Order)}
\begin{algorithmic}[1]
\STATE Compute $\ranku(t)$ and $\rankd(t)$, derive $\mathrm{biRank}(t)$
\STATE Build a priority ordering by descending $\mathrm{biRank}$
\STATE Initialize DP table $\mathrm{dp}[0..n-1][0..m-1] \leftarrow \infty$
\STATE For the first task, fill base cases: $\mathrm{dp}[0][v]=\EFT(t_0,v)$
\FOR{$i=1$ to $n-1$}
      \FOR{each previous VM $v_{prev}$ with finite dp}
            \FOR{each current VM $v_{curr}$}
                  \STATE $\mathrm{new} = \max(\mathrm{dp}[i-1][v_{prev}],\EFT(t_i,v_{curr}))$
                  \IF{$\mathrm{new} < \mathrm{dp}[i][v_{curr}]$}
                        \STATE update $\mathrm{dp}[i][v_{curr}]$ and parent pointer
                  \ENDIF
            \ENDFOR
      \ENDFOR
\ENDFOR
\STATE Backtrack from $\argmin_v \mathrm{dp}[n-1][v]$ to recover assignment
\STATE Replay assignments to produce final schedule
\STATE \textbf{return} complete schedule and makespan
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:} $O(n m^2 + m e)$ time and $O(n m (n+m))$ space in
the implemented snapshot-based realization (see \texttt{Edp.cpp}).

\textbf{Strengths/Limitations:} achieves global optimality subject to
the given priority order but is memory- and compute-intensive, making
it suitable for small-to-moderate DAGs or offline optimisation.

\textbf{Role:} provides a high-quality reference point (quality
ceiling) for rank-based schedules within the same C++ harness.

\subsection{Divide-and-Conquer (D\&C)}

\textbf{Overview:} D\&C partitions the DAG into topological levels
and treats each level as an independent scheduling subproblem, then
merges local solutions while enforcing cross-level dependencies.

\textbf{Workflow:} compute BFS levels (zero-indegree extraction), for
each level sort tasks by average execution time and assign greedily by
minimum EFT within the level; finally recompute global EST/EFT to
respect inter-level precedence and communication.

\begin{algorithm}[!t]
\caption{D\&C Level Scheduling}
\begin{algorithmic}[1]
\STATE Compute indegree for all tasks and collect entry tasks
\STATE Repeatedly extract current queue as a level and decrement successors' indegree
\FOR{each level $L$}
      \STATE Sort $L$ by descending average execution time
      \FOR{each task in sorted $L$}
            \STATE Assign to VM with minimal EFT (local greedy)
      \ENDFOR
\ENDFOR
\STATE Recompute EST/EFT globally to enforce cross-level dependencies
\STATE \textbf{return} merged schedule and makespan
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:} $O(n\log n + n m + e)$ time and $O(n+m+e)$ space
in the provided implementation (see \texttt{dac.cpp}).

\textbf{Strengths/Limitations:} very fast for wide/shallow DAGs but may
make suboptimal cross-level choices; merge phase preserves feasibility but
cannot fully reverse level-local decisions.

\textbf{Role:} lowest-overhead scheduler, useful when runtime cost is
the priority or as an initial solution for hybrid refinements.

\subsection{Min-Min (Greedy Level Heuristic)}

\textbf{Overview:} Min-Min is a classical greedy per-level heuristic
that repeatedly selects the task–VM pair with the minimum EFT and
commits it until the level is scheduled.

\textbf{Workflow:} for a level with remaining tasks compute for each
task the best VM (minimum EFT); choose the global minimum among these
best pairs, commit it, and repeat until the level is empty.

\begin{algorithm}[!t]
\caption{Min-Min Level Scheduling}
\begin{algorithmic}[1]
\STATE Let R be the set of unscheduled tasks in level
\WHILE{R not empty}
      \FOR{each task $t\in R$}
            \STATE compute best VM $v_t = \argmin_v \EFT(t,v)$ and its EFT
      \ENDFOR
      \STATE select $t^*=\argmin_{t\in R} \EFT(t,v_t)$, commit $t^*$ to $v_{t^*}$
      \STATE remove $t^*$ from R and update VM availability
\ENDWHILE
\STATE \textbf{return} level assignments
\end{algorithmic}
\end{algorithm}

\textbf{Complexity:} per-level worst-case $O(k^2 m)$, overall worst-case
$O(n^2 m)$ across levels; space $O(n+m+e)$.

\textbf{Strengths/Limitations:} simple and effective on homogeneous
levels; expensive on large levels and may suffer from global myopia.

\textbf{Role:} used as an alternative per-level strategy within the
Merge adaptive pipeline when variance is low.

\subsection{Merge Algorithm (Hybrid OP)}

\textbf{Overview:} Merge is an adaptive hybrid scheduler that selects
per-level strategies (D\&C, HEFT, Min-Min, DP-lookahead, or EDP) based
on level profile, and applies optional refinement passes to improve
the outcome.

\textbf{Workflow:} compute bilateral ranks and DAG profile; for each
level classify the most suitable local strategy and schedule it; build
an alternative global EDP schedule and choose the better initial
solution; apply iterative refinements (bottleneck migration, swaps,
DP replay, critical-path focus) if beneficial.

\textbf{Complexity:} variable depending on chosen per-level methods and
refinements; worst-case costly (see Table~\ref{tab:complexity}), but
practical on moderate DAG sizes due to adaptive selection.

\textbf{Strengths/Limitations:} flexible and often produces the best
makespan among implemented options; higher implementation complexity
and runtime when many refinement passes are enabled.

\textbf{Role:} highest-quality hybrid optimizer used as a final
refinement stage or for offline scheduling where runtime overhead is
affordable.

%  VII. COMPLEXITY ANALYSIS
% ============================================================
\section{Complexity Analysis}
\label{sec:complexity}

Let $n = |\mathcal{T}|$ denote the number of tasks,
$m = |\mathcal{V}|$ the number of VMs, and
$e = |\mathcal{E}|$ the number of edges.

\subsection{Per-Algorithm Complexity}

\begin{table}[!t]
\caption{Time and Space Complexity of Implemented Schedulers}
\label{tab:complexity}
\centering
\begin{tabular}{lcc}
\toprule
\textbf{Algorithm} & \textbf{Time Complexity} & \textbf{Space Complexity} \\
\midrule
HEFT & $O(n\log n + m\cdot(n+e))$ & $O(n + m + e)$ \\
DP-HEFT & $O(n\log n + n m^2 + m e)$ & $O(n + m + e)$ \\
EDP-HEFT & $O(m^2\cdot(n+e))$ & $O(n m (n + m))$ \\
D\&C & $O(n\log n + n m + e)$ & $O(n + m + e)$ \\
Merge (Hybrid) & $O(n m^2 + n m (n+e))$ & $O(n m (n + m))$ \\
\bottomrule
\end{tabular}
\end{table}

HEFT remains computationally efficient due to greedy assignment.
DP-HEFT adds a bounded look-ahead term. EDP-HEFT introduces a global
DP state space across task-VM combinations; in the implementation this
is realised by per-step snapshot copies (vm-ready vectors and per-task
finish/assignment arrays), which increases both memory usage and
copying overhead in practice. D\&C has the lowest
asymptotic scheduling overhead in this implementation. Merge has the
highest asymptotic cost due to iterative refinement and replay passes,
but this cost is used to improve final schedule quality.

\subsection{Comparative Analysis}

Based on Table~\ref{tab:complexity} and the default deterministic run
($n=40$, $m=7$, fixed seed 42), the following observations hold:
\begin{itemize}
  \item \textbf{Highest time complexity:} Merge (Hybrid), due to multi-pass
        refinement over full schedule replays.
  \item \textbf{Lowest time complexity:} D\&C, dominated by level sorting and
        linear merge constraints.
  \item \textbf{Highest space complexity:} EDP-HEFT and Merge, both requiring
        DP/snapshot state that scales with task-VM combinations.
  \item \textbf{Fastest execution in practice:} D\&C (lowest runtime overhead
        in the provided implementation).
  \item \textbf{Best (lowest) makespan:} EDP-HEFT and Merge tie at the best
        observed makespan in the default experiment.
  \item \textbf{Trade-off:} lower-overhead methods (HEFT, D\&C) run faster but
        may yield larger makespan; global/refined methods (EDP-HEFT, Merge)
        consume more compute and memory but improve scheduling quality.
\end{itemize}

\section{Results}

For the default deterministic DAG instance (implementation defaults), the observed makespan

quality over purely greedy or purely level-based baselines.
